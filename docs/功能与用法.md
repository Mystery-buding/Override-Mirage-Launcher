## 功能

| 功能 | 说明 |
|---|---|
| 版本清单 | 「下载」页读 Mojang 官方 `version_manifest_v2.json` 列出全部正式版；左下角整合包只显示本地已装好的版本 |
| **下载源切换** | 官方 / BMCLAPI 镜像一键切换，覆盖 Mojang 版本·资源·库、Fabric、Forge、NeoForge |
| 下载安装 | 客户端 jar、依赖库（含 natives 分类器）、资源文件、log4j 配置，逐项 SHA-1 校验 |
| 断点续装 | 已存在且大小匹配的文件直接跳过，重复点「校验 / 修复」即补全缺失文件 |
| **模组加载器** | Fabric、Quilt、Forge、NeoForge，见下节 |
| **模组 / 资源包 / 光影** | 下载页内置 Modrinth / CurseForge 搜索，可按 MC 版本与加载器筛选，一键装进 `instances/<id>/mods`、`resourcepacks`、`shaderpacks` |
| **版本继承** | 支持 `inheritsFrom`：把加载器版本与原版合并成一份可执行配置 |
| 启动游戏 | 按版本 JSON 动态拼装 JVM 与游戏参数，兼容 `arguments` 新格式与 `minecraftArguments` 旧格式 |
| Java 探测 | 扫描 JAVA_HOME、PATH、常见 JDK 目录、游戏目录下的 `runtime`，读 `java -version` 取主版本 |
| **版本隔离** | 每个整合包一套独立的 mods / 存档 / 配置（`instances/<id>`），版本、依赖库、资源仍共用，设置页可开关 |
| 内存控制 | 界面可调 `-Xmx`，默认 4096 MB |
| 本地库解压 | 自动把 natives jar 里的 dll 解到 `versions/<id>/natives` |
| **正版登录** | Microsoft 设备码授权 → Xbox Live → XSTS → Minecraft 服务，`refresh_token` 自动续期 |
| **离线登录** | 只填名字，UUID 由 `OfflinePlayer:<name>` 推算，正版/盗版模式随时切换 |
| 日志 | 全部写入 `logs/launcher-*.log`，界面不再占用版面显示 |
| 界面 | 窗口 1280×720（16:9）；左侧导航 + 常驻底部启动区；整合包是整行列表（每行右侧可删除），下载是整窗覆盖界面 |
| 命令行 | `--install` / `--combo` / `--installloader` / `--smokelaunch` / `--selftest` / `--uitest` |

## 模组加载器：本体 + 加载器一次装完

装整合包**只有一步**：在「下载」页选一个 MC 版本 → 在同一屏里挑加载器与加载器版本 → 点「安装」。
原版文件由安装流程内部作为依赖底座一起补齐，**不需要、也不会让你先装一遍本体再装一遍加载器**，装完列表里只多出 1 个整合包。

| 加载器 | 安装方式 | 说明 |
|---|---|---|
| 原版（不装加载器） | 直接装官方版本 | 客户端 jar + 依赖库 + 资源 |
| Fabric | 官方 meta 接口直接生成版本 JSON | 不需要 Java，几秒完成 |
| Quilt | 官方 meta 接口直接生成版本 JSON | 同上 |
| Forge | 下载官方 installer 并执行 `--installClient` | 需要 Java，耗时数分钟；自动生成 `launcher_profiles.json` |
| NeoForge | 下载官方 installer 并执行 `--installClient` | 同上；需能访问 `maven.neoforged.net` |

安装界面顶部一行是「← 返回 + 整合包名称输入框」，下面是**四行加载器菜单**（NeoForge / Forge / Fabric / Quilt，每行左侧是加载器图标），进入时四种加载器的版本并行预取并优先走国内镜像；点某一行展开该加载器的版本列表，选一个就定下来，名称框会自动填成 `26.3-NeoForge-26.3.0.95` 这种「版本-加载器-加载器版本」（可以自己改，留空则用加载器自带 id）。四行都不选就是装原版。菜单上方有一行摘要，写清这次装的是什么：

| 状态 | 摘要 |
|---|---|
| 没选加载器 | 「将安装 Minecraft 26.3 原版。要玩模组就展开下面任意一个加载器选一个版本，它会和本体一起装成同一个整合包。」 |
| 选了加载器 | 「将安装 1 个整合包：Minecraft 26.3 + NeoForge 26.3.0.95。原版文件会作为依赖一起装好，不需要再单独装一次本体。」 |

装完会出现在左下角整合包列表里（例如 `26.3-Fabric-0.20.1`、`26.3-NeoForge-26.3.0.95`），选中后直接点「启动游戏」。模组放各自整合包的目录（版本隔离开启时是 `.minecraft/instances/<id>/mods`，关闭时是 `.minecraft/mods`）。

一体化安装的实现在 `Core/CombinedInstaller.cs`，界面与命令行（`--combo`）共用同一条路径：

- 选了加载器 → `LoaderService.InstallAsync` 内部先跑一遍 `MinecraftInstaller`（补齐原版 jar / 依赖 / 资源），再装加载器；
- 没选 → 只跑 `MinecraftInstaller`；
- 最后按名称改一次名（名称为空 / 与默认 id 相同 / 不可用时保留默认 id，不会弹框打断）。

底座（`versions/26.3` 这种被 `inheritsFrom` 引用的原版）默认不显示在整合包列表里；**例外**：如果它自己有存档 / 模组 / 配置（`instances/<id>` 下非空），说明用户真的当整合包玩过，会继续显示，否则装完加载器后世界会看起来「消失」。

关键实现点：

- **版本列表来源**：Fabric / Quilt 读官方 meta；Forge 读 `maven.minecraftforge.net` 的 maven 元数据（`promotions_slim.json` 只登记 recommended / latest，新版本如 26.3 常常查不到）；NeoForge 读 `maven.neoforged.net`，该站连不上会在界面提示查询超时，切到 BMCLAPI 镜像后由镜像代取。所有加载器查询统一 20 秒超时，避免界面空转。
- **继承合并**：`VersionResolver` 把 `inheritsFrom` 链从顶层父版本开始向下合并。`libraries` 与 `arguments` 采用追加语义，`mainClass`、`assetIndex`、`javaVersion` 等子版本覆盖父版本。库去重键是 `group:artifact:classifier` —— 只用 `group:artifact` 会让 `org.lwjgl:lwjgl:3.4.3:natives-windows` 覆盖主 jar。
- **客户端 jar 归属**：加载器版本自身没有 jar，classpath 里的客户端 jar 取自继承链最顶层的原版。
- **本地构件**：Forge 的补丁客户端 jar（`forge-*-client.jar`）由安装器本地生成，`downloads.artifact.url` 为空。这类条目不能下载，但必须进 classpath，否则 Forge 启动时报 `Could not find .forge_patched_minecraft`。
- **Java 版本判定**：必须读合并后的 JSON。加载器版本自身通常没有 `javaVersion`，只看子版本会回落成 Java 8。

## 使用流程

界面左侧是导航（主页 / 下载 / 设置），右上内容区随导航切换（带滑入淡入动画，左侧指示条同步滑动）：

| 页面 | 内容 |
|---|---|
| 主页 | 登录方式切换（左正版 / 右离线）+ 用户名或账号信息 |
| 下载 | 点导航「下载」后**整窗覆盖**：左栏顶部是通栏「返回」，下面是来源（Minecraft / 模组 / 资源包 / 光影）+ 右侧五张**通栏的带边框分类卡片**（最新版 / 正式版 / 预览版 / 远古版 / 愚人节版），点卡片标题在内部缩进展开版本行（图标 + 版本号 + 日期），展开时卡片描边变绿，默认展开最新版；模组 / 资源包 / 光影则是 Modrinth 搜索页 |
| 设置 | Java 选择、游戏目录、最大内存、下载源、正版登录应用 ID、打开游戏目录 |

左侧栏从上到下是品牌、导航，最下面是常驻启动区：

- 通栏「启动游戏」按钮；
- 下一行「整合包选择」按钮（显示当前图标与名字，点开是整行列表）；
- 再下一行通栏「整合包设置」按钮，弹出菜单：打开整合包目录 / 打开 mods 文件夹（版本隔离开启时是当前整合包专属的 `instances/<id>/mods`）/ 校验修复 / 安装加载器（后两项分别走修复流程与「下载」页）。

整合包选择界面是**整行列表**：每行左侧图标、中间名称与加载器（当前使用的那行标「使用中」并高亮），最右侧是**「打开文件夹」**与**「删除」**两个按钮。

- 「打开文件夹」在资源管理器里打开该整合包的**运行目录**（版本隔离开启时是 `instances/<id>/`，关闭时是 `versions/<id>/`），mods、存档、配置都在里面；
- 「删除」会二次确认，然后删掉 `versions/<id>/` 整个目录（版本 JSON、客户端 jar、natives）；删的正好是当前整合包时会一并清掉配置里的版本 id。如果 `instances/<id>/` 里还有内容，会再问一句要不要连同存档一起删。如果有别的整合包 `inheritsFrom` 指向它，确认框里会列出这些子版本并提示删了它们会起不来。

列表**不显示依赖底座**：装模组加载器时会自动装一份原版（例如 `26.3`）供 `inheritsFrom` 引用，它不是用户主动装的整合包，因此只要还有别的版本继承它、且它自己没有存档 / 模组 / 配置，就不会出现在选择列表里（否则删掉之后解析器会把它重新拉回来，看着像「删不掉」）。如果这个底座里确实用户内容（`instances/<id>` 下有存档或模组），会照常显示，避免装完加载器后世界像「消失」了一样。

用户名在输入后 400 毫秒自动写回 `config.json`，关窗前也会再存一次，不用先点一次「启动游戏」才会记住。

行内图标优先用 `versions/<id>/icon.png`（也认 jpg/jpeg/webp），没有就用加载器徽标（NF / FG / FB / QL），原版则显示草方块。

进度条与状态提示平时收起，只在下载 / 安装 / 启动时出现，结束 4 秒后自动隐藏；运行日志统一写到 `logs/` 目录，界面不再占用版面。

1. 在「主页」页选登录方式：正版（左）点「使用 Microsoft 账号登录」，离线（右）直接填用户名。
2. 第一次用先点左侧「下载」，进入整窗的下载界面（左栏顶部的「返回」可退出）：来源选 Minecraft（模组 / 资源包 / 光影 走 Modrinth 搜索，见下节），右栏是五张带边框的分类卡片，点标题在卡片内展开缩进的版本列表（默认展开「最新版」，里面是最新正式版与快照）。点任意一行版本进入安装界面：顶部一行是「← 返回 + 整合包名称输入框」，上面一行摘要说明这次装什么，下面是四行加载器菜单，展开任意一个挑个版本（不选就装原版），右下角「安装」——本体和加载器一次装完，装完列表里只多出 1 个整合包并自动选中它。
3. 要换加载器不需要先装原版：直接再来一遍，选另一个加载器即可，原版底座是共用的，不会重复下载。
4. 到「设置」页确认 Java 不低于该版本要求（1.20.5+ 需要 Java 21，1.18–1.20.4 需要 Java 17，更早需要 Java 8）。
5. 回左下角点「启动游戏」。文件损坏或缺失时，在「版本与模组」页点「校验 / 修复」补全。

启动使用当前选中的登录方式；在正版页点「退出登录」会回到离线模式。

「游戏目录」默认是 exe 同级的 `.minecraft`，可改到已有整合包目录，启动器会复用里面的版本与资源。

## 版本隔离（每个整合包一套 mods / 存档）

所有整合包的 mods 都堆在 `.minecraft/mods` 时，换版本就会互相打架（1.20 的 mod 装进 1.21 直接崩）。启动器默认开启**版本隔离**：每个整合包有自己的运行目录，共享的部分仍然只有一份。

```
.minecraft/
├─ versions/<id>/        每个整合包一份：版本 JSON、客户端 jar、natives
├─ libraries/            所有整合包共用（不重复下载）
├─ assets/               所有整合包共用（不重复下载）
└─ instances/<id>/       每个整合包一份：mods / config / saves / resourcepacks / shaderpacks / screenshots
```

要点：

- **开关**：设置页「整合包隔离」复选框（`IsolateInstances`，默认开）。关掉就退回旧行为——所有整合包共用 `.minecraft` 根目录。切换立即生效并写入 `config.json`，下一次启动按新设置走。
- **启动方式**：`game_directory` 变量与进程的 `WorkingDirectory` 都指向 `instances/<id>`，游戏自己写 mods、存档、`options.txt` 时自然落在里面；classpath、资源、依赖库仍从共用的 `versions` / `libraries` / `assets` 读。
- **旧内容迁移**：第一次用独立目录启动时，如果 `.minecraft` 根目录下有非空的 `mods / config / resourcepacks / shaderpacks / saves / screenshots`，会自动搬进该整合包的独立目录（日志里会写「已把 config\ 迁移到 …」）。搬不动（例如游戏正在占用）会记一条警告并给出手动复制的提示。
- **打开文件夹**：整合包行右侧的按钮打开的是**运行目录**（隔离开启时是 `instances/<id>`），目录还没建出来会先创建，可以直接往里丢 mod。
- **删除整合包**：默认只删 `versions/<id>`；如果 `instances/<id>` 非空，会多问一句——「是」连同存档一起删，「否」只删版本保留存档，「取消」什么都不做。

## 模组 / 资源包 / 光影（Modrinth + CurseForge）

下载页左侧的「模组 / 资源包 / 光影」三个来源可以各选一个数据源，界面上有三个筛选控件：

| 控件 | 选项 | 说明 |
|---|---|---|
| 游戏版本 | 跟随整合包 / 全部版本 / 具体版本 | 「跟随整合包」沿 `inheritsFrom` 找当前整合包的原版号；具体版本列表取自官方清单里的正式版 |
| 加载器 | 跟随整合包 / 全部 / Fabric / Forge / NeoForge / Quilt | 只对模组生效，资源包与光影的下拉会置灰 |
| 数据源 | Modrinth / CurseForge | 见下面两节 |

选完自动重搜；结果行右侧显示「选择版本」，点行展开版本列表，点某个版本即下载，装完状态变成「已安装 <版本号>」。

### Modrinth

走 [Modrinth](https://modrinth.com) 的开放接口（不需要 API Key，只带 User-Agent）：

- **搜索**：`GET /v2/search`，用 `facets` 组合过滤 `[["project_type:mod"],["versions:<MC版本>"],["categories:<加载器>"]]`，按相关度取前 20 条；留空关键词就是按热度浏览。
- **版本**：点结果行展开，才去拉 `GET /v2/project/<id>/version`，按发布时间倒序，最多渲染 30 条（大项目版本数以千计）。
- **下载**：取 `files` 里的 primary 文件，按 `sha1` / `size` 校验后写进 `instances/<当前整合包>/mods`、`resourcepacks` 或 `shaderpacks`；已存在同名文件会提示而不重复下载。
- **图标**：项目图标下到 `cache/icons/` 做磁盘缓存；Modrinth 的图标有不少是 webp，WPF 解不了，这时保留按标题生成的字母块（颜色由标题字符和决定）。

### CurseForge

[CurseForge](https://www.curseforge.com/minecraft) 的第三方接口（`api.curseforge.com/v1`）**强制要求 API Key**：到 <https://console.curseforge.com> 注册一个应用即可免费拿到，填在**设置页 → CurseForge** 里，点「保存」写进 `config.json` 的 `CfApiKey`。没填 Key 时选中该来源只会提示去填，不会报错中断（Modrinth 不受影响）。

- **搜索**：`GET /v1/mods/search`，参数 `gameId=432`、`classId`（6 = 模组，12 = 资源包，6552 = 光影）、`searchFilter`、`gameVersion`、`modLoaderType`（1 = Forge，4 = Fabric，5 = Quilt，6 = NeoForge），请求头带 `x-api-key`。
- **版本**：`GET /v1/mods/<id>/files`，`gameVersions` 里混着加载器名，会被拆成单独的加载器列表；`downloadUrl` 为空的老文件按 `https://media.forgecdn.net/files/<id/1000>/<id%1000>/<fileName>` 拼回 CDN 地址。
- **下载**：`hashes` 里 `algo = 1` 的是 SHA-1，与 `fileLength` 一起交给下载器校验。
- `--selftest` 的第 [8] 项会在填了 Key 时顺带测一次 CurseForge 搜索，没填就跳过。

## 方块图标

下载页版本行左侧的图标用的是 Minecraft 社区**通用的方块造型图标**（`Grass.png`、`CommandBlock.png`、`CobbleStone.png` 等 64×64）：HMCL、PCL 等多个启动器都有同类素材，**并非某一家的专属素材**。本项目的 PNG 文件取自 [Meloong-Git/PCL](https://github.com/Meloong-Git/PCL) 仓库 `Plain Craft Launcher 2/Images/Blocks/` 中的切片，已放进 `Assets/Blocks/` 并作为 WPF 资源内嵌；若造型源自游戏内方块，版权归 Mojang。署名与出处见 `CREDITS.md`。

查找优先级：`images/blocks/*.png`（用户覆盖）→ 内嵌素材 → 程序生成的纹理（兜底，素材缺失时仍能显示）。

**换成自己的图**

1. 运行 `--exporticons`，把当前生效的图标原样导出到 `images/blocks/`：`grass.png`、`command.png`、`dirt.png`。
2. 用画图 / Photoshop / Aseprite 改，或按下面 Blockbench 流程从零做。
3. 存回 `images/blocks/`（同名覆盖）。日志会写 `使用自定义方块图标：...`。

**用 Blockbench 从零做（和 PCL 美术同款流程）**

1. 装 [Blockbench](https://www.blockbench.net/)，新建 `Java Block/Item` 项目。
2. 导入 16×16 方块贴图（从资源包 jar 的 `assets/minecraft/textures/block/` 里取，如 `grass_block_top.png`、`grass_block_side.png`）。
3. 在 UV 面板把顶面贴 top 图、四个侧面贴 side 图。
4. 视角切到等轴测（右上角视图预设），背景设为透明。
5. `File → Export → Export Image`，导出 256/512 的 PNG。
6. 放进 `images/blocks/`，文件名用 `grass.png` / `command.png` / `dirt.png`。

> Minecraft 原始贴图版权归 Mojang，自用没问题，随启动器分发要谨慎。

## 界面动画实现

- **页面切换**：旧页 110ms 淡出后收起；新页从导航方向一侧滑入 28px 并淡入（260ms，`CubicEase/EaseOut`）。
- **指示条**：左侧竖条用 `TranslateTransform.Y` 动画滑到 `index * 44`，与页面切换同步。
- **导航悬停**：模板内单独一层 `Border`，用 `Trigger.EnterActions/ExitActions` 做透明度过渡，不改变布局。
- **下载界面**（`Core/UiAnim.cs` 统一提供，全部走代码动画，方便给动态生成的行加延迟）：
  - 覆盖层开关：打开时淡入 + 从左侧滑入 16px；关闭先淡出 + 左移再收起（140ms），导航高亮在动画结束后复位。
  - 右侧三个视图（分类 / 内容搜索 / 安装器）互相切换时淡入 + 横滑 22px。
  - 分类卡片展开：列表高度从 0 撑到实测高度（260ms），箭头旋转 90°，行按 18ms 间隔错峰淡入；标题与卡片描边同步变绿。
  - 行悬停：背景色用 `ColorAnimation` 过渡（160ms），不再是瞬间跳色；画笔每次都换成该行自己的实例，避免动到共享的静态画笔。
  - 安装视图里四行加载器菜单依次淡入（40ms 间隔）；Modrinth 搜索结果按 24ms 间隔错峰淡入，展开的版本列表同理。
- **自检**：`--uitest` 会等 Java 与本地整合包扫描完（最多 8 秒），再依次切换 0→1→2→1→0，校验每页可见性、切换后透明度是否为 1.00、指示条 Y 是否为 0/88/132（下载占了导航第二格）、页面内容是否超出可视区（超出但已包 ScrollViewer 只提示可滚动，无法滚动才算异常）；最后打开/关闭一次下载覆盖层，校验它横跨两列、「最新版」快捷入口已生成、退出后导航高亮已复位，再切到「模组」来源真搜一次关键词、校验结果行渲染出来（超过 25 秒没结果才报错），结论写入 `uitest.log`；还会对主页的正版 / 离线切换与用户名输入框各做一次**命中测试**（`InputHitTest`），确认它们没有被别的元素挡住（设置页那层 ScrollViewer 曾经一直盖在主页上，导致「看得见点不到」）；再真装一个模组，校验装完后行上的「下载中…」换回版本信息、状态变成「已安装 …」，测试下载的文件会自动删掉；还会开一次安装视图，校验四行加载器菜单都建出来、摘要非空，并真的等 NeoForge 的版本列表拉回来（最多 30 秒）后展开菜单选一个版本，校验自动命名与「1 个整合包」摘要都正确；最后开整合包选择界面，校验行数与本地整合包数量一致、每行都有两个操作按钮。
