## 网络与下载源

设置页的「下载源」可在**官方源**与 **BMCLAPI 镜像**之间切换，它只决定**谁先试**：版本清单、加载器版本查询、Forge / NeoForge 安装器下载都会在失败后自动换另一个源，单个源 10 秒超时，因此不切也能用（只是首个源不通时会多等一次超时）。改完立即生效，清单缓存会清空，已下载的文件不需要重下：

| 源 | 覆盖范围 |
|---|---|
| 官方 | Mojang（清单 / 版本 JSON / 客户端 jar / 库 / 资源）、Fabric、Quilt、Forge、NeoForge |
| BMCLAPI | 同上，另含 Forge / NeoForge 的 maven 与安装器；**Quilt 没有镜像，仍走官方** |

常见故障：`maven.neoforged.net` 在部分网络下不可达，官方源会 10 秒超时后自动改用镜像，实测仍能列出 26.3 的 25 个 NeoForge 版本（26.3.0.95 起），安装器也能正常下载。在设置里把下载源改成镜像可以让这类查询从 ~10.6 秒降到 ~0.9 秒。镜像的 Forge 版本表偶尔比官方少，需要历史版本时可切回官方源。

### 安装器依赖预置

Forge / NeoForge 走的是官方安装器 jar（`java -jar installer.jar --installClient`），**安装器自己会再去 `maven.neoforged.net` / `maven.minecraftforge.net` 拉库**，启动器的下载源开关管不到它。在这些 maven 不可达的网络里，安装器会打印 `These libraries failed to download` 并以退出码 1 结束。

解决办法是跑安装器之前先把依赖下好：

1. 读取安装器 jar 内的 `version.json` 与 `install_profile.json`，取出 `libraries[].downloads.artifact`；
2. 已存在且 SHA1 匹配的文件直接跳过，其余走 `MavenCandidates(url, preferMirror: true)` 镜像优先、8 并发下载到 `<gameDir>/libraries`；
3. 整个安装过程用 `DownloadSource.PreferMirror()` 强制走镜像；
4. 依赖齐全后再执行安装器，此时它只会校验本地文件，不再联网。

实测 NeoForge 26.3.0.95 预置 25 个文件后安装成功，全程约 13 秒。Forge 走同一条路径，同样受益。

### NeoForge 运行时补丁

NeoForge 1.21+ / 26.x 的官方安装器写完版本 JSON 就算完事，但那份 JSON 是**半份**的：

- 没有 `net.neoforged:neoforge:<版本>:universal`（NeoForge 本体 jar）；
- 没有它自己生成的 `net/neoforged/minecraft-client-patched/<版本>/...jar`；
- 而 FML 启动时偏偏要在 classpath 里找 `net/minecraft/client/<mc版本>-<neoform版本>/client-...-srg.jar`。

结果就是能装完、一启动就报：

```
[GameLocator] Failed to find required file net\minecraft\client\26.3-1\client-26.3-1-srg.jar
[FMLLoader] Your NeoForge installation is corrupted. Please try to reinstall NeoForge.
```

`Core/NeoForgeRuntime.cs` 负责补齐，安装后自动跑一次，启动前也会检查一次（所以已经装坏的整合包点「启动游戏」就能自愈，不用重装）：

1. 把安装器生成的 `minecraft-client-patched-*.jar` 复制成 FML 认的 `net/minecraft/client/<mc>-<neoform>/client-<mc>-<neoform>-srg.jar`，并在 `META-INF/MANIFEST.MF` 主段补上 `Minecraft-Dists: client`（FML 会检查这个标记）；
2. 把 universal jar 与 srg jar 以「本地构件」写进版本 JSON 的 `libraries`——有 `path` 但 `url` 为空，因此只进 classpath、不会被当成需要下载的文件。

实测 26.3 + NeoForge 26.3.0.95 装完后启动正常：模组列表里 `Minecraft 26.3` 与 `NeoForge 26.3.0.95` 都在，资源与声音引擎加载完成。

> 顺带一提：`versions/<原版>/<原版>.jar` 是所有加载器整合包共用的客户端 jar。在整合包列表里删掉原版，继承它的加载器整合包就会报「缺少客户端 jar」——删除时启动器会列出受影响的子版本做提示。

## 实现说明

- **参数求值**：先按 `rules` 过滤（`os.name` / `os.arch` / `features`），再把 `${...}` 占位符替换掉；未知占位符替换为空串。带 `features` 的规则一律不匹配 —— quickPlay 的几个互斥参数就是靠它区分的。
- **classpath**：取所有非 natives 的库外加客户端 jar，用 `;` 连接。
- **natives**：新格式（`name` 含 `:natives-`）与旧格式（`natives.windows` 分类器）都支持，按库名分类器过滤架构，解压时只取 `.dll`。
- **本地库路径**：`-Djava.library.path` 统一在 JVM 参数末尾追加，覆盖版本 JSON 的默认值，同时包含根目录与 `java`/`jna`/`lwjgl`/`netty` 子目录。
- **离线 UUID**：`MD5("OfflinePlayer:<name>")` 并按 UUID v3 置位，与主流启动器一致。
- **正版参数**：`auth_uuid` 传 32 位无连字符形式，`user_type=msa`，`clientid` 取 Azure 应用 ID；离线则 `user_type=legacy`、`auth_access_token=0`。
- **整合包图标**：`ModpackCatalog` 沿 `inheritsFrom` 链识别加载器（改名后的整合包也能认出来），`ModpackIcons` 按「icon.png → 加载器徽标 → 草方块」的顺序绘制，全部矢量生成，不依赖图片资源。
- **版本行**：下载页版本不再用下拉框，改成 PCL 风格的行列表——左侧方块图标（正式版草方块、预览版命令方块、远古版圆石，素材来自 PCL，见「资源致谢」），右侧版本号与「发布于 yyyy/M/d HH:mm」，选中行绿框高亮；安装器视图用可滚动列表，窗口再小也不会被裁掉。图标可用 `images/blocks/*.png` 覆盖，见上文「方块图标」。
- **页面宿主**：`PageHost` 里的页面是叠放的，只要有一层铺满且没折叠，就会把下面页面的点击全部吃掉。设置页因为内容比可视区高被包了一层 `ScrollViewer`，**这层 ScrollViewer 才是页面宿主**（`ShowPage` 切换的就是它），不显示时必须 `Collapsed`，否则主页的正版 / 离线切换与用户名会变成「看得见点不到」。`--uitest` 会用 `InputHitTest` 逐个验一遍。
- **整合包命名**：改名不是只改显示——`PackNaming` 会搬 `versions/<id>` 目录、重写版本 JSON 的文件名与 `id` 字段、同步改名 `<id>.jar`，最后把其它版本里 `inheritsFrom` 指向旧 id 的引用一起改到新名字；中途失败会尝试回滚。名称限制 32 字符、不能含 `\ / : * ? " < > |`、不能与已有整合包重名。
